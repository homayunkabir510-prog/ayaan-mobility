# Dependency migration and security references

- **Prisma ORM v6-to-v7 upgrade guide:** https://www.prisma.io/docs/guides/upgrade-prisma-orm/v7 — Prisma 7 is a breaking upgrade; update `prisma` and `@prisma/client` together, use the `prisma-client` generator with explicit output, move datasource URLs into `prisma.config.ts`, and supply a PostgreSQL driver adapter when constructing `PrismaClient`.
- **Prisma ORM v7 PostgreSQL pool guidance:** https://www.prisma.io/docs/orm/v7/prisma-client/setup-and-configuration/databases-connections/connection-pool — the `pg` adapter uses the Node.js PostgreSQL pool; defaults include `max: 10`, `connectionTimeoutMillis: 0`, and `idleTimeoutMillis: 10,000`. This project intentionally sets a finite pool size and explicit timeouts; production must size pool connections against hosting/database limits.
- **Prisma Config reference:** https://www.prisma.io/docs/orm/v7/reference/prisma-config-reference — Prisma CLI loads `prisma.config.ts` for every command; `prisma generate` itself does not need a live database URL, so config may provide an empty fallback while deploy/validation commands receive `DATABASE_URL` explicitly.
- **GitHub Advisory GHSA-ggr8-5vv4-36mx (deepmerge-ts):** https://github.com/advisories/GHSA-ggr8-5vv4-36mx — versions `<8.0.0` are affected; `8.0.0` is patched. The resolved Prisma 7.10.1 tree uses `deepmerge-ts@8.0.2`.
- **GitHub Advisory GHSA-7589-6fvf-x4pw (Effect):** https://github.com/advisories/GHSA-7589-6fvf-x4pw — versions `<=3.22.0` are affected; `3.22.1` is patched. Prisma CLI's pinned `@prisma/config@7.10.1` dependency resolves `effect@3.20.0`, so the project uses an explicit npm override to `effect@3.22.1`; generation, validation, migration, typecheck, build, and the audit gate must remain green for this override to be retained.
- **Verification source:** `npm audit --audit-level=high` against the resulting lockfile returned `found 0 vulnerabilities` after applying the narrowly scoped override and regenerating the Prisma 7.10.1 client.
